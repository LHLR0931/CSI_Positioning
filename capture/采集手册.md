## 1. 硬件与 AP 配置

| 设备 | 型号 | 说明 |
|---|---|---|
| AP × 2 | GL.iNet GL-SFT1200（Opal），全球版 | 逻辑名称为 apX、apY；实际 BSSID 分别通过 `CSI_APX_BSSID`、`CSI_APY_BSSID` 配置；只做发帧源，不需要 Nexmon |
| 流量客户端 × 2 | 两部手机，用 ping app 持续 ping 所连 AP，间隔 100 ms（app 的下限）：手机 1 连 apX 并 ping apX 网关；手机 2 连 apY 并 ping apY 网关；屏幕常亮、app 保持前台 | 一个客户端只能关联一个 AP，所以每台 AP 各需一个。实测 ping 间隔调到 100 ms 前后，AP 帧占比均在 22%–23%；正式采集每条链路约 9.8 帧/秒，与信标间隔 102.4 ms 一致 → 推测 CSI 主要来自信标帧（间接推断，未逐帧解析帧类型） |
| 接收端 × 2 | Raspberry Pi 4B（BCM43455 + Nexmon） | 逻辑名称为 piA、piB；SSH 地址分别通过 `CSI_PIA_HOST`、`CSI_PIB_HOST` 配置 |

**拓扑**：两台 AP 同在 ch36 / 20 MHz、不同 SSID / BSSID；两台 Pi 都 monitor 在 ch36、不关联 AP、不按 MAC 过滤（`FILTER_MAC=0`），解析时按 BSSID 拆成 2 Pi × 2 AP = 4 条链路。
**射频选择理由**（论文用）：家中有多台路由器（含邻居），80 MHz 等宽带宽会造成同信道干扰，所以用 20 MHz；搭建阶段试过其他信道，ch36 最稳定。

### 1.1 AP 配置（LuCI / SSH，锁死 20 MHz）

```sh
ssh root@<ap-admin-address>
uci set wireless.radio0.country='AU'
uci set wireless.radio0.hwmode='11a'
uci set wireless.radio0.channel='36'
uci set wireless.radio0.htmode='HT20'
uci set wireless.radio0.disabled='0'
uci set wireless.default_radio0.mode='ap'
uci set wireless.default_radio0.ssid='csi_ap_a'     # 第二台 csi_ap_b
uci set wireless.default_radio0.encryption='psk2'
uci set wireless.default_radio0.key='<set-a-unique-password>'
uci commit wireless && wifi reload
iw dev                            # 核对 ch36 / 20 MHz
```

关闭两台 AP 的自动固件更新与自动选信道。为什么锁 20 MHz：配 40 MHz 时小包常以 20 MHz 发出，接收端会拿到半空的 CSI。

### 1.2 验收（新装或换设备后）

AP 连续运行不重启；`iw reg get` 显示 AU；`nexutil -k` 返回 36/20；两个 BSSID 都在持续发帧；每秒包率稳定；CSI 为 64 个位置、有效子载波不是大面积为零；连续采 10–30 分钟无掉线、形状不变；重启后配置可复现。

常见问题：5 GHz 起不来 → 多为 country 未设 AU 或用了 DFS 信道；WiFi6 AP 的 HE 帧 BCM43455 抓不了（SFT1200 是 WiFi5，无此问题）。

## 2. 场地与摆位

### 2.1 坐标系与标记

以网格左下角格点为原点，x 向右、y 向前，单位米。格点 `(x, y)`，x = 0…4，y = 0…2，位置 `(0.8x, 0.8y)`，`label = y × 5 + x`。网格占地 3.2 m × 1.6 m。
地面用美纹纸贴 15 个十字标记并写上 label，**十字中心 = 双脚中点**。卷尺量过，误差 < 10 cm。

### 2.2 设备坐标（已做几何优化，按此摆放；配套图 `report/figures/layout_plan_zh.svg` 和 `layout_plan_en.svg`）

| 设备 | x (m) | y (m) | 高度 | 位置 |
|---|---:|---:|---:|---|
| apX | +0.75 | −0.70 | 0.75 m | 网格前方偏左 |
| apY | +4.10 | −0.30 | 1.35 m | 网格右前方远端 |
| piA | −0.90 | +2.00 | 1.10 m | 网格左后方 |
| piB | +2.65 | +2.20 | 0.60 m | 网格正后方偏右 |

高度**特意各不相同**（平面优化之外再加一层不对称）。房间净空约 5.6 m × 3.5 m。摆放精度 ±10 cm 即可。
**四台设备位置贴地面胶带，并拍俯视全景 + 每台特写**：这是跨日复位的唯一依据，否则无法区分"环境漂移"和"设备放歪"（反射物挪 λ/2 = 2.9 cm 指纹就会变）。

### 2.3 走位（蛇形）

```
第 3 排 (y=2)：10 → 11 → 12 → 13 → 14
第 2 排 (y=1)： 9 →  8 →  7 →  6 →  5
第 1 排 (y=0)： 0 →  1 →  2 →  3 →  4
```

### 2.4 为什么这样摆（论文实验设计章节可用）

可分性判据用超量程差 δ = |AP→人| + |人→Pi| − |AP→Pi|：δ 相同的格点落在以 AP、Pi 为焦点的同一椭圆上，这条链路分不开它们。对称布置时格点 2 与 12 四条链路 δ 完全相同（最小可分度 0）；本方案融合最小可分度 0.558 m（中位 2.676 m）。四条链路各自都有近简并的点对，但**各不相同**（piA_apX 4↔9、piA_apY 7↔10、piB_apX 7↔13、piB_apY 5↔10），融合后最小可分度提升约 860 倍。σ = 10 cm 的摆放误差下 5% 分位仍有 0.484 m。

## 3. 树莓派设置（两台都做，每次开机都做）

### 3.1 本机配置与连通

在仓库根目录打开 PowerShell，填写本次实际使用的设备信息。这些值只在当前终端会话中生效，不要把真实地址或口令写入仓库：

```powershell
$PiAHost = "<piA-address>"
$PiBHost = "<piB-address>"
$env:CSI_PIA_HOST = $PiAHost
$env:CSI_PIB_HOST = $PiBHost
$env:CSI_APX_BSSID = "<apX-bssid>"
$env:CSI_APY_BSSID = "<apY-bssid>"
```

- [ ] 两台都能免密 SSH：`ssh "pi@$PiAHost" "echo ok"`、`ssh "pi@$PiBHost" "echo ok"` 都直接返回 ok（脚本用 `BatchMode=yes`，有密码提示会直接失败）
- [ ] `dmesg | grep -i nexmon` 看到打补丁的固件（曾经软链指向未打补丁的固件，抓不到 CSI）

### 3.2 拷新版脚本（**下次采集第一件事**：Pi 上目前还是 10-11 之前的旧版 setup）

```powershell
scp .\capture\pi\csi_setup.sh   "pi@${PiAHost}:/home/pi/csi_setup.sh"
scp .\capture\pi\csi_setup.sh   "pi@${PiBHost}:/home/pi/csi_setup.sh"
scp .\capture\pi\csi_capture.sh "pi@${PiAHost}:/home/pi/csi_capture.sh"
scp .\capture\pi\csi_capture.sh "pi@${PiBHost}:/home/pi/csi_capture.sh"
```

### 3.3 跑 setup，看两行自检

```powershell
ssh "pi@$PiAHost" "bash /home/pi/csi_setup.sh"
ssh "pi@$PiBHost" "bash /home/pi/csi_setup.sh"
```

- [ ] `CHECK power : Power Management:off`
- [ ] `CHECK nm    : wlan0:unmanaged`

新版 setup 会让 NetworkManager 放手 wlan0、在网卡 up 之后关闭无线省电（每次 `ifconfig up` 内核都会重新打开省电，所以顺序不能反）。D+3 改之前 54 分钟断流 3 次，改之后 84 分钟（75 个点）0 次。`phase2_capture.ps1` 开采前也会检查这两项，不满足就拒绝开采。

### 3.4 对时（Pi 没有电池时钟，不对时 pcap 日期全错）

```powershell
ssh "pi@$PiAHost" "sudo date -u -s '$((Get-Date).ToUniversalTime().ToString('yyyy-MM-dd HH:mm:ss'))'"
ssh "pi@$PiBHost" "sudo date -u -s '$((Get-Date).ToUniversalTime().ToString('yyyy-MM-dd HH:mm:ss'))'"
(Get-Date).ToUniversalTime().ToString('HH:mm:ss'); ssh "pi@$PiAHost" "date -u +%T"; ssh "pi@$PiBHost" "date -u +%T"
```

- [ ] 三行时间相差 ≤ 2 秒

### 3.5 状态与预热

- [ ] `vcgencmd get_throttled` 返回 0x0；`df -h /tmp` 空间够
- [ ] **从通电算起满 10 分钟**再开标定轮
- [ ] 采集期间**不要拔插 Pi 的网线**（10-08 拔线后 piA 停止输出 CSI）。要确认哪台是 piA，用闪灯：
  `ssh "pi@$PiAHost" "L=/sys/class/leds/ACT; [ -d `$L ] || L=/sys/class/leds/led0; echo timer | sudo tee `$L/trigger >/dev/null; sleep 10; echo mmc0 | sudo tee `$L/trigger >/dev/null; echo done"`

## 5. 冒烟测试（开采前最后一关）

```powershell
.\phase2_capture.ps1 -Session smoke -Round 1 -Only 0
.\phase2_capture.ps1 -Session smoke -Round 1 -Only 12
```

按时间采集：每点 42 秒，beacon 每 102.4 ms 一帧，约 410 帧 / 链路。四个数都应在 400 左右（≥ 380 绿色 OK）。

| 看到什么 | 说明 | 怎么办 |
|---|---|---|
| 四个数都在 380–420 | 正常 | 开采 |
| 同一台 AP 的两条链路一起偏低（两台 Pi 上都低） | 同信道其他 AP 干扰 | 重采；第二、三次通常会恢复 |
| 某一条是 0 | 那台 AP 没开 / 不在 ch36 / BSSID 不对 | 查第 4 节 |
| 某台 Pi 两条都是 0 | Pi 断流 | 见第 7 节 |
| scp FAILED | SSH 或磁盘问题 | 查 3.1 / 3.5 |

测完删掉 `data\smoke\`。

## 6. 正式采集

```powershell
.\phase2_capture.ps1 -Session <新session名> -Round 1 -RoomNote "门关 窗关 室温22 衣服黑 鞋白"
```

- **session 名不能和已有的重复**（d1、d3 已用；下一天例如 `d6`，按实际距 D1 的天数命名）。目标 pcap 已存在时脚本会拒绝，除非加 `-Force`。
- 单点重采：`-Only <label>`；跳过某点须输入 `skip`，会记入 `session_meta.json`。
- 验证日的轮次安排：r1 = 标定 c1，r2–r4 = t1–t3（连续、不停、不走动），可选 r5 = t4（标定后约 90 分钟）。**用途要在采集前写进预登记**，采完在 `backend/data/sessions.py` 登记。
- 纪律：每轮之间走出布点区再进入；房间里不要有第二个人走动；动了任何东西立刻写进 RoomNote；三次采集穿同一套衣服和鞋；RoomNote 写室温。
- 两段之间**不要关设备**（关了射频状态会重置，要重新标定）。

## 7. 断流与异常处理

**现象**：某台 Pi 两条链路同时掉到 0（另一台正常），5 秒抓包 `total=0`，重跑 setup 无效。至今**没有证据表明会自己恢复**（10-08 那次之前记成"自行恢复"是错的，实际是手动重启）。

**快速恢复（约 20 秒，不用重启）**：先 Ctrl+C 停脚本，在出问题的那台 Pi 上：

```bash
sudo modprobe -r brcmfmac_wcc; sudo modprobe -r brcmfmac; sleep 2; sudo modprobe brcmfmac; sleep 8
bash /home/pi/csi_setup.sh        # 两行自检都要对
```

然后 5 秒抓包确认恢复。**驱动重载等同于网卡重启：当前这一轮作废，下一轮改为重新标定**（这条规则要写进预登记）。

**异常数据别删**：把异常尝试的 pcap 另存到 `data\<session>\anomaly_r<N>_label<L>_try<K>\`（不在 `phase2_r*` 下，不进训练），它们是健康分 / 漂移分析的天然样本。

**采集脚本卡住**：脚本里 ssh / scp 已有硬超时；若仍卡住，`Get-Process ssh` 找到 PID 后 `Stop-Process`。
